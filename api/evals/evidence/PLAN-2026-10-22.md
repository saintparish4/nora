# Analysis plan: the model pass, a ConText filter, and a medspaCy baseline

Written 2026-10-22, before any condition below was run. Committed before the
runs so the commit history shows the order. Anything decided after seeing
results is labelled exploratory in the report.

## Question

Can the model pass be added to the rule pass without handing reviewers more
wrong quotes? And how does a standard non-LLM clinical NLP baseline (medspaCy
with ConText) compare with both?

## What has already been seen (disclosure)

- Round `model_baseline` (rules + gpt-4o-mini, 3 reps) was scored on both
  slices before this plan, and its wrong excerpts, test slice included, were
  read and tagged (`taxonomy.yml`). The test slice is therefore not untouched
  for any model condition. Results on it are reported, but they are evidence
  of a lesser kind than a sealed test set would give (see PROTOCOL.md, sealed
  test set).
- medspaCy's default ConText rules were tried on five hand-written sentences
  to check the install. They flagged negation and family history, and missed
  "discussed ... declined" and "advised to start".

## Conditions

| Id | Condition | How it is produced |
|---|---|---|
| R | Rules only | A fresh run of the current rule pass, round `rules`. Must match v3 exactly (deterministic); if not, stop and explain. |
| M | Model alone | Round `model_alone`: `MODEL=on ABLATE=hints REPS=3`. With every rule hint removed the rule pass proposes nothing (selfcheck `selfcheck_no_hints`), and the model's input does not depend on hints, so this records every model excerpt, including those the service would drop as duplicates of rule excerpts. |
| RM | Rules + model, as the service does it | Derived per rep: R's excerpts, then M's, dropping a model excerpt that overlaps a rule excerpt on the same criterion and document (the service's `add_evidence` rule). |
| G | Model only where rules found nothing | Derived per rep: R's excerpts, plus M's excerpts on criteria where R proposed nothing. |
| F | Rules + model through a ConText filter | Derived per rep: R's excerpts, plus those of M's excerpts that pass the filter below, deduplicated as in RM. |
| B | medspaCy baseline alone | Round `medspacy`: the extractor below, no rules, no model. Deterministic, 1 rep. |

RM, G and F reuse the same model outputs, so the comparisons among them are
paired on identical model behaviour; only the combination rule differs.

Model: `gpt-4o-mini` (the app's default; the served snapshot is recorded),
current prompt (digest `1f3a82360afda028`), 3 reps. Expected cost about $0.04.
Stop if a two-case pilot shows more than twice the token use of
`model_baseline`.

## The ConText filter (condition F)

medspaCy 1.3.1 default pipeline (PyRuSH sentences, target matcher, ConText
with its shipped rules, unmodified). Targets for each criterion are the
criterion's own hint vocabulary from the policy library (`terms`, `drugs`,
`comorbidity_terms`, `also_requires`), plus "BMI" and "body mass index" for the
BMI criterion. For each model excerpt:

- Criterion 6 (no concurrent GLP-1): keep only if a GLP-1 target in it is
  NEGATED_EXISTENCE.
- Every other criterion: keep if at least one target in it carries none of
  NEGATED_EXISTENCE, POSSIBLE_EXISTENCE, HYPOTHETICAL, FAMILY; and, for the BMI
  criterion only, not HISTORICAL.
- An excerpt with no target in it is dropped.

Expected costs, stated in advance: excerpts phrased without the hint
vocabulary (the `wording` type) will be dropped, so F may find less than RM.
The default rules do not cover "declined", "discussed" or "advised", so F is
not expected to remove the `hypothetical` errors.

## The medspaCy baseline (condition B)

Same pipeline and targets. Every sentence of every document is a candidate.
A sentence is proposed for a criterion when, with the same modifier rules as
the filter:

1. BMI: it states a BMI value ("BMI", "body mass index", or a Z68.xx code
   followed by a number), in a document dated within 6 months of the request;
   value 30 or more, or 27 to 29.9 and an affirmed comorbidity target anywhere
   in the chart. Not HISTORICAL.
2. Diagnosis: an affirmed diagnosis target.
3. Comorbidity: an affirmed comorbidity target.
4. Lifestyle: an affirmed diet target and an affirmed activity target in the
   same sentence. No duration check (ConText has none).
5. Prior trial: an affirmed target for a weight-management drug other than the
   one requested (HISTORICAL allowed), and one of: stopped, discontinued,
   d/c, lost, loss, no weight, side effect, intolerance, nausea, because.
6. No concurrent GLP-1: a NEGATED GLP-1 target.
7. Second trial: as 5, proposed only when the chart yields sentences for two
   different drug groups.

This shares the rule pass's vocabulary on purpose: it isolates what ConText
adds over hand-written rules, not what a different word list adds.

## Metrics and tests

- Per-case `clean`, `found`, `precision`, `verbatim`, averaged over cases;
  reps averaged within a case first (score.py does this).
- Each condition against R, paired by case, 95% bootstrap intervals, on the
  test slice. Five comparisons per metric, so Bonferroni-corrected intervals
  (alpha 0.01) decide whether a difference is claimed.
- Order of importance: `clean` (a wrong quote a reviewer may approve is the
  costly error), then `precision`, then `found`.
- Per-type scores from `taxonomy.yml` (`eval:evidence:taxonomy`), descriptive
  only: no tests on cells this small.
- Train slice reported alongside, and the only slice read for failure detail.

## Decision rule, fixed now

A condition could replace the rule pass as the default only if its `clean`
interval against R lies entirely above -5 points and its `found` interval lies
entirely above 0. With 9 test cases for `clean`, the interval is about 25
points wide either way, so this eval cannot establish that. The expected
outcome is "not demonstrated", and nothing changes in the app on the strength
of this round. A condition that is clearly worse (interval entirely below 0
on `clean`) is ruled out for these cases.

## What would change this plan

Nothing after the runs start. If a run fails or a derived round does not
reproduce what it should (R differs from v3), the runs stop, the cause is written down, and the plan is amended in
a new dated section above the results, not edited in place.
